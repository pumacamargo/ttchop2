# Own sales vs external references (TTChop2)

Analytics has two deliberately separate paths. "Mis Analytics / ventas propias" parses a TikTok Shop order export and writes `analytics_orders/{uid}/orders` after the user explicitly confirms it came from their own shop. Its `imports/{id}` record has `type: sales_file`, `sourceKind: own`. Historical `sales_file` imports lack `sourceKind`; they retain their previous order-analytics behavior, but the imports manager identifies their origin as not explicitly recorded. This is user-declared provenance, not a TikTok verification.

"Referencias externas" requires a source name supplied by the user, writes `type: sales_reference`, `sourceKind: external`, `sourceLabel: <name>` to `imports/{id}`, and stores workbook rows only under `sales_reference_data/{uid}/rows`. Neither the source label nor the filename proves ownership. Earlier `sales_reference` imports without explicit provenance display **Origen sin verificar**. They remain references; no migration or live records are changed by this feature.

`accountId` is only a **storage/visibility container**, never sales provenance. Selecting a connected account (or reassigning the import in Manage Imports) files the document there; the general container remains visible in each account. This does not establish which TikTok shop generated a workbook. The source fields are distinct from `accountId`. The reference listing and Manage Imports display source status separately from the container.

Own-sales totals, top-product rankings, charts, Dashboard and Reports use order rows, gated by `visibleOwnOrders`: rows linked to references, external imports or missing imports are excluded even if accidentally placed in `analytics_orders`; legacy order rows without an `importId` retain historical behavior. Reference rows are never read by this calculation path. There is no reference-vs-own comparison in this UI; adding one later requires an explicit opt-in and source labels for every series. Do not relabel legacy references as own sales or aggregate references into own metrics based on filename, products or container.

Workflow: choose the own-sales path only for your shop's export and confirm ownership; otherwise enter an external source name and upload as reference. Review the resulting source badge and filename in the reference list/Manage Imports. To inspect historical files without source fields, treat them as unverified; reassignment of a container never changes their provenance. Deployment and Firestore migration are separate approvals.
